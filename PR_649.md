# Proposal: Make Prover Dependencies Required

## Issue

Fixes #649 (W2-Z-005).

The SDK currently declares `@aztec/bb.js`, `@noir-lang/noir_js`, and
`@noir-lang/noir_wasm` as optional dependencies. Package installation can
therefore succeed without the prover, while proof generation fails later at
runtime.

## Proposed Change

Update `sdk/package.json` so all three prover packages are declared under
`dependencies` or `devDependencies`, as appropriate for the SDK's runtime and
build usage, and remove them from `optionalDependencies`.

Regenerate the SDK lockfile after updating the manifest. No runtime fallback
should be added: proof generation requires these packages.

## Validation

Add or update SDK package-management tests to verify that:

- Each prover package is present in a required dependency section.
- None of the prover packages is listed in `optionalDependencies`.
- A clean install with a missing prover package fails during dependency
  installation rather than during proof generation.

Run the SDK dependency validation and test commands in CI using the project's
supported package manager.

## Acceptance Criteria

- Installing the SDK cannot silently omit a required prover dependency.
- Proof generation has its required prover packages available after a
  successful install.
- The SDK lockfile reflects the required dependency graph.

## Repository Scope Note

This repository checkout currently contains the Soroban Rust contracts but no
`sdk/` directory, `package.json`, JavaScript lockfile, or Noir package source.
The implementation and package-install tests must be applied in the SDK
repository or branch containing that package before this proposal can be
converted into a code change.
