# Contracts – Known Issues

Issues found in the smart contracts (acbu_minting, acbu_burning, acbu_oracle, acbu_reserve_tracker, acbu_savings_vault, acbu_lending_pool, acbu_escrow, shared). Add new items below as numbered list entries.

---

## Critical

1. **Missing access control on escrow `release`** – acbu_escrow/src/lib.rs: `release` has no auth check. Any address can call `release(escrow_id)` and send funds to the payee.
2. **Unrestricted minting in `mint_from_fiat`** – acbu_minting/src/lib.rs: `mint_from_fiat` does not validate `fintech_tx_id` or off-chain fiat deposits. With `check_admin_or_user`, the recipient can call it for themselves and mint ACBU without real fiat backing.
3. **Escrow ID collision** – acbu_escrow/src/lib.rs: Escrow keys use only `(ESCROW, escrow_id)`. Two payers can use the same `escrow_id`; the second create overwrites the first. The first payer's funds become unrecoverable. ✅ **Resolved (#192):** EscrowId now includes payer address: `EscrowId(pub Address, pub u64)`. Keys are `(payer, escrow_id)`, preventing collisions between different payers using the same escrow_id. Covered by `acbu_escrow/tests/test.rs::test_different_payers_can_reuse_same_escrow_id_without_collision` and `acbu_escrow/tests/test_edge_cases.rs::test_two_payers_same_escrow_id_independent`.
4. **Incorrect total supply in `verify_reserves`** – acbu_reserve_tracker/src/lib.rs: `verify_reserves` uses `acbu_client.balance(&env.current_contract_address())` as total supply. The reserve tracker does not hold ACBU, so this is always 0. The function returns `true` early and reserve checks never actually run.
5. **Missing auth checks in savings vault** – acbu_savings_vault/src/lib.rs: `deposit` and `withdraw` lack `user.require_auth()`. Anyone can call `withdraw(user=X, term_seconds=Y, amount=Z)` and move funds without X's authorization.
6. **Missing auth checks in lending pool** – acbu_lending_pool/src/lib.rs: `deposit` and `withdraw` lack `lender.require_auth()`. Anyone can call `withdraw(lender=X, amount=Y)` and drain X's balance.
35. **No overflow protection on `mint_from_usdc` amount calculation** – acbu_minting/src/lib.rs: The conversion `usd_amount * rate / DECIMALS` uses unchecked arithmetic. On Stellar/Soroban with `i128`, values near `i128::MAX` overflow silently, minting a corrupted amount.
36. **Escrow `refund` does not debit payer balance before transfer** – acbu_escrow/src/lib.rs: `refund` calls `token_client.xfer(&payer, &env.current_contract_address(), &amount)` (transfer FROM payer TO escrow), then transfers back to payer. If the payer has insufficient balance in step 1, the transfer fails but partial state may already be updated.
37. **`mint_from_fiat` fintech TX ID validation uses exact match but is case-sensitive** – acbu_minting/src/lib.rs: The `fintech_tx_id` duplicate check stores and compares the raw string. Fintech partners may normalize TX IDs differently (uppercase, strip dashes), allowing duplicate mints with equivalent-but-not-identical IDs.
38. **Reserve tracker `total_reserves` computed without checking all currency keys** – acbu_reserve_tracker/src/lib.rs: `total_reserves` iterates a stored list of currency keys. If a currency key was added after the iteration list was last updated, it is silently excluded from the total, masking reserve shortfalls.
39. **No `#[panic_with_error]` handler in escrow, lending, and savings contracts** – acbu_escrow/src/lib.rs, acbu_lending_pool/src/lib.rs, acbu_savings_vault/src/lib.rs: These contracts lack the standard error-to-panic mapping. A contract error (`Err(Error::X)`) propagates as an opaque `ScErrorType::Contract` with no structured error code for the client.

## High

7. **Term not enforced in savings vault** – acbu_savings_vault/src/lib.rs: `term_seconds` is stored but never checked on withdrawal. Users can deposit and withdraw immediately; there is no lock period. ✅ **Resolved (#199):** `withdraw` only credits lots where `now >= lot.timestamp + lot.term_seconds` and rejects an under-matured `amount` with `InsufficientUnlocked`. Covered by `acbu_savings_vault/tests/test_lock_and_interest.rs` (`test_withdraw_before_term_fails`, `test_withdraw_one_second_before_term_fails`, `test_withdraw_at_exact_term_boundary_succeeds`).
8. **No max amount check in `mint_from_fiat`** – acbu_minting/src/lib.rs: `mint_from_usdc` enforces `max_mint_amount`, but `mint_from_fiat` only checks `min_amount`, allowing unbounded minting. ✅ **Resolved (#200):** `mint_from_fiat` now loads `max_mint_amount` and rejects `usd_gross > max_amount` (and `< min_amount`) with `InvalidMintAmount`, matching `mint_from_usdc`. Covered by `acbu_minting/tests/test_mint_from_fiat.rs::test_mint_from_fiat_above_max_amount`.
9. **Integer division truncation in `burn_for_basket`** – acbu_burning/src/lib.rs: `amount_per_account = acbu_after_fee / (recipient_accounts.len() as i128)` truncates. With many recipients, dust is lost and never accounted for.
10. **No duplicate escrow check** – acbu_escrow/src/lib.rs: `create` does not check if `escrow_id` already exists. Overwriting an existing escrow can lock prior funds.
11. **Oracle and reserve tracker unused in minting** – acbu_minting/src/lib.rs: `oracle` and `reserve_tracker` are loaded but never called. Rates are hardcoded to 1:1 and reserve checks are skipped.
12. **Oracle and reserve tracker unused in burning** – acbu_burning/src/lib.rs: Same as minting — oracle and reserve tracker are loaded but not used; rates are hardcoded.
40. **`admin_set_rate` in oracle does not emit `RateUpdateEvent`** – acbu_oracle/src/lib.rs: The admin rate override function updates storage but doesn't emit the standard rate-update event. Backend listeners tracking `RateUpdateEvent` miss admin-forced rate changes.
41. **`burn_for_basket` iterates recipients in serial with cross-contract calls** – acbu_burning/src/lib.rs: For each recipient account, the contract makes a cross-contract token transfer. With 100 recipients, this may exceed the Soroban per-transaction CPU instruction limit.
42. **No minimum balance enforcement after withdrawal in lending pool** – acbu_lending_pool/src/lib.rs: After a `withdraw`, the lender's remaining balance may be 1 stroop. Future operations on dust balances cause precision errors and unnecessary storage entries.
43. **Savings vault `deposit` does not verify the token transfer succeeded before recording** – acbu_savings_vault/src/lib.rs: `deposit` records the deposit in storage BEFORE calling `token_client.xfer()`. If the token transfer fails (e.g., user has no balance), the storage shows a deposit that never happened.
44. **`get_rate_by_currency` returns 0 for unregistered currencies without error** – acbu_oracle/src/lib.rs: If a currency is not in the oracle, the function returns `0` instead of an error. Minting 1000 USD worth of ACBU against a 0 rate would produce a division-by-zero panic or divide-by-zero mint amount.
45. **Lending pool `borrow` does not check if lender has sufficient unborrowed balance** – acbu_lending_pool/src/lib.rs: The borrower specifies `lender: Address` and `amount: i128` but the contract doesn't verify that the lender has `deposited_amount - already_borrowed >= amount`. Borrowers can over-borrow from a single lender.
46. **No `require_auth` on `update_reserves` in reserve tracker** – acbu_reserve_tracker/src/lib.rs: `update_reserves` modifies the core reserve data but has no auth check at all. Any address can set arbitrary reserve values for any currency, fabricating solvency.
47. **Oracle `submit_rate` validator deduplication uses raw Vec iteration** – acbu_oracle/src/lib.rs: Checking `if !validators.contains(&validator)` on every submission uses O(n) linear scan per validator. With 50 validators submitting each epoch, the per-transaction CPU cost grows quadratically.
48. **`set_fee_rate` in minting contract does not validate fee_bps <= BASIS_POINTS** – acbu_minting/src/lib.rs: `set_fee_rate` accepts any `fee_bps` value. A fee > 10,000 basis points (>100%) silences the mint entirely or causes integer underflow in fee calculation.
49. **Burning contract `redeem_single` does not verify the recipient account exists on Stellar** – acbu_burning/src/lib.rs: Funds may be burned to an uninitialized or nonexistent Stellar account. The token transfer succeeds (Stellar creates accounts via `create_account` operation in the token contract), but the funds become inaccessible if the destination is a typo.
50. **No check that oracle validator set size >= minimum before median calculation** – acbu_oracle/src/lib.rs: `update_rate` computes the median of the current epoch's submissions. If only 1 validator submits (others offline), the "median" is a single potentially malicious rate with no safety net.
51. **Multisig contract admin threshold can be set to 0** – acbu_multisig/src/lib.rs: `initialize` or `set_threshold` may accept `threshold: 0`. Zero-signature proposals execute immediately with no authorization, equivalent to no multisig at all.
52. **`pause`/`unpause` in minting contract does not validate caller is admin** – acbu_minting/src/lib.rs: If `pause()` is implemented with `check_admin_or_operator`, an operator can pause the contract. Pausing should be admin-only; operators should only be able to mint/burn.
53. **Lending pool interest calculation can divide by zero if `total_deposits == 0`** – acbu_lending_pool/src/lib.rs: `interest_rate = annual_rate * elapsed_seconds / (365 * 24 * 3600)` or similar — the contract must guard against zero total deposits before computing interest factors.
54. **No storage bounds check on escrow lifetime** – acbu_escrow/src/lib.rs: Escrow entries persist forever with no `ledger.sequence()` or `ledger.timestamp()` expiry. An attacker can create millions of 1-stroop escrows, exhausting contract storage and bricking the escrow contract.

## Medium

13. **Token WASM import uses zero SHA256** – In acbu_minting, acbu_burning, and acbu_reserve_tracker, `soroban_token_contract.wasm` is imported with `sha256 = "0x0000...0"`. This is a placeholder; production builds should use the real WASM hash for integrity and security.
14. **Double `.unwrap().unwrap()` in escrow** – acbu_escrow/src/lib.rs: Multiple storage reads use `.get(...).unwrap().unwrap()`. Storage `get` returns `Option<T>`, so a single `.unwrap()` is expected. The second `.unwrap()` may panic or indicate a type mismatch.
15. **Double `.unwrap().unwrap()` in savings vault** – acbu_savings_vault/src/lib.rs: Same problematic double-unwrap pattern. ✅ **Resolved (#210):** no chained `.unwrap().unwrap()` remains; storage reads use `unwrap_or_else(|e| env.panic_with_error(e))` / explicit error handling.
16. **Double `.unwrap().unwrap()` in lending pool** – acbu_lending_pool/src/lib.rs: Same pattern. ✅ **Resolved (#211):** no chained `.unwrap().unwrap()` remains; storage reads use safe `unwrap_or_else` / explicit error handling.
17. **Outlier detection has no effect in oracle** – acbu_oracle/src/lib.rs: Outliers are detected but only marked with a comment "Log outlier but continue with median". No logging, rejection, or alert occurs.
18. **Incorrect oracle test assertion** – acbu_oracle/tests/test.rs: Test expects `stored_rate == rate` (1234567), but the contract stores `median(sources)` (1235000). The test will fail.
19. **Redundant calculation in burning** – acbu_burning/src/lib.rs: `(acbu_after_fee * DECIMALS) / DECIMALS` is equivalent to `acbu_after_fee`; the multiplication and division cancel out.
20. **`median` uses `to_vec()` in no_std** – shared/src/lib.rs: `median` allocates with `values.to_vec()`. In `no_std` Soroban contracts this may not be available or may require `alloc`.
21. **Contract events vs backend listeners** – Verify that MintEvent and BurnEvent payloads (field names, types, decimals) match what the backend event listeners expect, to avoid parsing or indexing failures.
55. **`shared::median` sorts in descending order but contract expects ascending** – shared/src/lib.rs: `median` uses `sort_by(|a, b| b.cmp(a))` (descending). The median of [100, 200, 300] descending-sorted is [300, 200, 100], where index `len/2` picks 200. This is coincidentally correct for odd-length but wrong for even-length (should average two middle elements).
56. **Oracle `update_rate` sets epoch timestamp without verifying it is newer** – acbu_oracle/src/lib.rs: The epoch timestamp is set to `ledger.timestamp()` without checking it's >= the previous epoch timestamp. On networks with clock drift or testnets that reset time, older epochs overwrite newer ones.
57. **Burning `redeem_basket` fee applied after-split causes precision loss** – acbu_burning/src/lib.rs: Fee is applied to the total `acbu_amount`, then the remainder is split among recipients. The opposite order (split then fee) would produce different rounding on each recipient. The current approach is correct but untested for edge divisibility cases.
58. **`mint_from_fiat` includes `admin_drip` path that bypasses fintech validation** – acbu_minting/src/lib.rs: The `admin_drip_demo_fiat` function may be callable as a sub-path within `mint_from_fiat` rather than a separate entry point. If the admin drip logic is reachable without admin auth, it's a direct mint exploit.
59. **Savings vault `term_seconds` stored as `u64` but compared using `i128`** – acbu_savings_vault/src/lib.rs: Type mixing (`u64` vs `i128`) may cause the term comparison to use incorrect signedness. `u64::MAX as i128` is a valid non-negative value, but comparisons with `ledger.timestamp()` (i128) may have unintended sign behavior.
60. **Lending pool `repay` does not emit `RepaymentEvent` or update loan state** – acbu_lending_pool/src/lib.rs: `repay` may exist in the contract but does not record repayment or emit an event. The loan appears outstanding forever, and off-chain systems cannot reconcile.
61. **`admin_drip_demo_fiat` mints to `msg.sender` not to a specified recipient** – acbu_minting/src/lib.rs: Admin drip mints to the caller (admin). If the intent is to seed test user accounts, this requires the admin to send funds in a second transaction, doubling gas and failure modes.
62. **Oracle `get_median_rate` returns 0 if no validators have submitted** – acbu_oracle/src/lib.rs: Before the first epoch submission, `get_median_rate` returns 0. Any mint or burn operation that queries the oracle before the first submission gets a rate of 0 and either divides by zero or produces 0 ACBU.
63. **`set_fee_rate` event emitted before storage write, listener sees old value** – acbu_minting/src/lib.rs: Events are emitted before the storage `set`. Backend event listeners query the contract state after receiving the event and get the old fee rate, creating a one-epoch inconsistency.
64. **Reserve tracker `add_currency` does not check for duplicate currency** – acbu_reserve_tracker/src/lib.rs: `add_currency` pushes to a `Vec` without checking if the currency already exists. Iteration-based lookups (`contains`) on a duplicated currency double-count reserves, inflating the reported total.
65. **No `#[contractversion]` attribute on any contract** – All contracts: Soroban's `#[contractversion]` tracks the ABI version for forward compatibility. Without it, the SDK cannot detect breaking changes between contract versions, and clients may call outdated interfaces.
66. **`create_escrow` does not validate `payee != payer`** – acbu_escrow/src/lib.rs: An escrow can be created with `payee == payer`. The funds circulate from the payer's account to the escrow contract and back, costing gas with no economic purpose. Self-escrow can also be used to artificially inflate volume metrics.
67. **Savings vault `get_user_lots` returns all lots with no pagination** – acbu_savings_vault/src/lib.rs: A user with many deposit lots (savings ladder strategy) calls `get_user_lots` which tries to return the entire `Map` in one invocation. Large maps may exceed Soroban's return value size limit.
68. **`verify_reserves` function is public with no auth but mutates nothing** – acbu_reserve_tracker/src/lib.rs: A public function that anyone can call but does not change state. Bots or attackers can spam `verify_reserves` calls to increase ledger load with no cost or rate limit.
69. **Minting `initialize` does not validate that admin and operator are different addresses** – acbu_minting/src/lib.rs: If the same address is set as both admin and operator, all operator-level checks are bypassed (admin has all permissions). This defeats the two-role security model.
70. **Lending pool `set_interest_rate` uses admin but operator can also call** – acbu_lending_pool/src/lib.rs: Interest rate changes affect all lenders and borrowers. If an operator (who may handle day-to-day minting) can also change lending rates, a compromised operator can set exorbitant rates.
71. **No `#[event]` struct for `FeeRateUpdated` in minting or burning** – acbu_minting/src/lib.rs, acbu_burning/src/lib.rs: Fee rate changes modify storage but don't emit a typed event. Backend listeners have no way to know the fee changed except by polling.
72. **Escrow `release` uses `token_client.xfer_from` but sender must first approve** – acbu_escrow/src/lib.rs: `xfer_from` requires the escrow contract to have been approved as a spender. The approve step may be missing, causing all `release` calls to fail with `TransferNotAllowed`.
73. **Oracle `remove_validator` does not remove the validator's pending submission** – acbu_oracle/src/lib.rs: If a validator is removed mid-epoch, their submitted rate remains in the epoch's submissions list. The median calculation includes data from an ex-validator.
74. **`shared::StorageKey` enum variants use different string lengths causing storage fragmentation** – shared/src/lib.rs: `Symbol::new(&env, "total_supply")` (13 bytes) vs `Symbol::new(&env, "fee")` (3 bytes). Uneven key sizes cause storage slot fragmentation, increasing per-contract storage costs on Soroban.
75. **`build.rs` does not fail the build on WASM hash mismatch** – build.rs: The WASM integrity check may print a warning instead of calling `panic!()`. A mismatched token WASM is detected but the build continues, producing a binary that will fail only at runtime.
76. **`acbu_lending_pool/src/lib.rs.bak` committed to the repository** – acbu_lending_pool/: A `.bak` backup file was committed. It contains duplicate contract logic and may be confused with the actual implementation during code review or refactoring.
77. **No `phase` or lifecycle state enum for contracts (Init, Active, Paused, Upgraded)** – All contracts: `pause`/`unpause` toggle a boolean but don't track which phase the contract is in. After an upgrade, there's no way to tell the difference between "paused for maintenance" and "not yet initialized."
78. **Escrow `release` transfers to `payee` but doesn't verify `payee` is the stored payee** – acbu_escrow/src/lib.rs: `release(escrow_id)` sends funds to the escrow record's `payee` field. If `create_escrow` stored the wrong payee (attacker-controlled), `release` dutifully sends funds to the attacker.
79. **`#[contracterror]` enum variants lack descriptive numeric codes** – All contracts: Error enums use default ordinal numbering (0, 1, 2...). Explicit `#[error(X)]` annotations ensure ABI stability — adding a new variant shifts all subsequent error codes, breaking client error handling.

## Low

22. **Magic number for fee cap in savings and lending** – ✅ **Resolved (PR #143):** acbu_savings_vault and acbu_lending_pool now use `shared::BASIS_POINTS` constant instead of hardcoded `10_000`, consistent with minting and burning.
23. **Incorrect fee in per-account BurnEvent** – acbu_burning/src/lib.rs: Each `BurnEvent` uses `calculate_fee(amount_per_account, fee_rate)`, but the fee is taken from the total `acbu_amount`. Per-account fees in events don't match actual fee accounting.
24. **`yield_amount` always 0 in savings** – acbu_savings_vault/src/lib.rs: `WithdrawEvent` always sets `yield_amount: 0`, suggesting yield logic is not implemented.
25. **Fee rate stored but unused in lending pool** – acbu_lending_pool/src/lib.rs: `fee_rate` is stored during initialization but never applied to any operation.
26. **Fee rate stored but unused in savings vault** – acbu_savings_vault/src/lib.rs: Same — `fee_rate` is stored but not applied.
27. **Loan events never emitted** – acbu_lending_pool/src/lib.rs: `LoanCreatedEvent` and `RepaymentEvent` are defined but never emitted; lending/repayment logic appears missing.
28. **No tests for core minting flows** – acbu_minting/tests/test.rs: Tests cover init, pause, and fee rate, but not `mint_from_usdc` or `mint_from_fiat`.
80. **`unused_variables` warning suppressed with `_` prefix but variable still computed** – Multiple contracts: `let _fee = calculate_fee(amount, rate);` suppresses the compiler warning but still executes the computation, wasting gas on a result that's immediately discarded.
81. **Oracle `update_rate` calls `median` even when only 1 submission exists** – acbu_oracle/src/lib.rs: Computing the median of a single-element array is unnecessary. A special case for `submissions.len() == 1` saves gas by skipping sort and median logic.
82. **`burn_for_basket` `Vec::new` allocates empty Vec for zero recipients** – acbu_burning/src/lib.rs: When `recipient_accounts.len() == 0`, the function still allocates several Vecs and iterates, wasting gas on a no-op burn.
83. **`shared::BASIS_POINTS` re-exported but some contracts redeclare `const BASIS_POINTS: i128 = 10_000`** – acbu_lending_pool/src/lib.rs, acbu_savings_vault/src/lib.rs.bak: Duplicate constant declarations risk one getting out of sync if the value ever changes (e.g., migrating to 100_000 for higher precision).
84. **`env.storage().set()` called with the same key in multiple places** – acbu_minting/src/lib.rs: The same storage key is set in both `initialize` and `mint_from_fiat`. Encapsulating storage keys in a module prevents accidental key collisions.
85. **No `#[test]` attribute on utility functions in shared crate** – shared/src/lib.rs: `median`, `calculate_fee`, and other pure functions lack unit tests in the shared crate. Bugs in shared utilities replicate to all dependent contracts.
86. **`token_client.xfer()` error not differentiated from other errors** – Multiple contracts: Cross-contract token transfer errors return as a generic `ContractError::TransferFailed` without preserving the underlying Soroban error. Debugging a token transfer failure requires re-running with verbose logging.
87. **Savings vault `get_term_end` returns `timestamp + term_seconds` without overflow check** – acbu_savings_vault/src/lib.rs: `ledger.timestamp() + term_seconds` can overflow `u64` on networks with epoch timestamps. An overflow causes the term to appear as already expired, releasing funds early.
88. **`initialize` functions don't check if contract was already initialized** – acbu_escrow/src/lib.rs: Most contracts check `already_initialized` before running `initialize`, but escrow may not. Re-initializing overwrites admin, fee rates, and other critical state.
89. **No `is_initialized()` getter for off-chain readiness checks** – Multiple contracts: Backend services have no way to check if a contract has been initialized before calling its functions. Uninitialized contracts return cryptic storage-not-found errors.
90. **`CurrencyCode` in shared uses `Vec<SorobanString>` but lacks `is_empty()` check on iteration** – shared/src/lib.rs: Iterating an empty `CurrencyCode` is harmless but wastes gas on an iterator setup/teardown. Functions should early-return on empty currency lists.
91. **Escrow `get_escrow` returns `(payer, payee, amount)` tuple but order differs from `create_escrow` parameters** – acbu_escrow/src/lib.rs: The parameter order `(payer, payee, amount)` in `create_escrow` doesn't match the return order of `get_escrow` (e.g., `(amount, payer, payee)`). This mismatch causes off-by-field bugs in client code that destructures the response.
92. **No `#[allow(dead_code)]` annotation on event types that are only emitted** – Multiple contracts: Event structs that are only emitted (never read in-contract) trigger dead-code warnings. Explicit allow annotations prevent warnings from masking real dead code.
93. **`require_auth` called multiple times for the same address in a single function** – acbu_minting/src/lib.rs: Some functions call `user.require_auth()` and `admin.require_auth()` separately. If `user == admin`, Soroban charges auth twice for the same address unnecessarily.
94. **No `contractevent` attribute on emitted events** – Some contracts: Events defined without `#[contractevent]` or the new-style `#[event]` are not emitted as structured Soroban events or use the wrong ABI encoding.
95. **`cargo test` runs on all contracts even when only one changed** – Cargo.toml: The workspace `cargo test` compiles and tests all contracts. A single-contract change triggers compilation and testing of all 8 contracts, slowing CI feedback.
96. **`Cargo.lock` committed but Soroban contracts don't benefit from lockfiles** – Cargo.lock: Soroban contracts compile to WASM with `--target wasm32-unknown-unknown`, but the lockfile includes non-WASM dependencies. The lockfile grows large without providing WASM reproducibility.
97. **No `rust-toolchain.toml` to pin rustc/soroban-sdk version** – Project root: Without a pinned toolchain, different developers compile with different Rust and Soroban SDK versions. WASM hashes differ, CI verification fails, and deployed contracts may behave differently.
98. **`admin_drip_demo_fiat` has `demo` in the name but exists in production code** – acbu_minting/src/lib.rs: Functions with "demo" in the name suggest test-only code that was never removed. If this is production, it should be renamed; if test-only, it should be behind `#[cfg(test)]`.
99. **Savings vault `deposit` event includes `term_seconds` but not `maturity_timestamp`** – acbu_savings_vault/src/lib.rs: The event stores the term length but not the computed maturity time. Off-chain systems must recompute it, and if the ledger timestamp at event time differs from the current ledger timestamp, they get the wrong maturity.
100. **Lending pool `deposit` event missing `lender` field** – acbu_lending_pool/src/lib.rs: The deposit event may include amount but not the lender address. Off-chain balance tracking cannot attribute deposits to specific users without parsing the transaction envelope.
101. **Oracle `rate_decimals` hardcoded to 7 in contract but backend uses different** – acbu_oracle/src/lib.rs: `const DECIMALS: u32 = 7` may not match the backend's decimal handling. A mismatch causes the backend to display rates 10x or 100x off.
102. **`shared::ContractError` enum variants not documented with `///` comments** – shared/src/lib.rs: Error variants have no docstrings. Client developers must read contract source to understand what each error means and when it's returned.
103. **No `#[doc]` attribute on public contract entry points** – Multiple contracts: Public functions lack doc comments. The generated Soroban SDK documentation is empty, making integration harder for frontend and backend developers.
104. **`test_snapshots/` directory references not updated after contract refactoring** – acbu_minting/test_snapshots/: Snapshot files may reference old variable names or event field names. If the snapshots are not regenerated after refactoring, snapshot-based tests pass with stale data.

## Trivial

29. **Unused import** – acbu_minting/src/lib.rs: `Vec` is imported but not used.
30. **`len() == 0` style** – acbu_burning/src/lib.rs: `recipient_accounts.len() == 0` could be `recipient_accounts.is_empty()`.
31. **Empty validators in event** – acbu_oracle/src/lib.rs: `RateUpdateEvent` uses `validators: Vec::new(&env)` instead of the actual validator set.
32. **Weak `transaction_id` generation** – acbu_minting/src/lib.rs: `transaction_id` is `format!("mint_{}", ledger.sequence())`, which is predictable and not globally unique.
33. **No events in reserve tracker** – acbu_reserve_tracker/src/lib.rs: Reserve updates do not emit events, making off-chain tracking harder.
