# Fix: W10-RUST-008 - Clean up and verify assert_recipient_is_account in mint_from_fiat

## Issue
Fixes #1051 (W10-RUST-008)

## Problem Statement
The Wave 10 audit finding W10-RUST-008 flagged that `mint_from_fiat` omitted the C-058 recipient-is-account check (`assert_recipient_is_account(recipient)`), posing a risk of ACBU being minted to contracts lacking token-receipt logic and stranding funds.

## Findings & Changes

1. **`mint_from_fiat` Verification**:
   - `mint_from_fiat` in `acbu_minting/src/lib.rs` (line 1029) already invokes `Self::assert_recipient_is_account(&recipient);` immediately following `operator.require_auth()`.
   - Comprehensive test coverage is established in `acbu_minting/tests/test_mint_from_fiat.rs` via `test_mint_from_fiat_rejects_contract_recipient()`.

2. **Clean up Merge Residue in `assert_recipient_is_account`**:
   - Resolved a merge collision in `acbu_minting/src/lib.rs` originating from merge commit `24269c8`.
   - Removed unclosed dead code inside `assert_recipient_is_account` and restored clean delegation to `shared::is_account_address` per AC-031 / C-058:
     ```rust
     fn assert_recipient_is_account(address: &Address) {
         if !is_account_address(address) {
             address.env().panic_with_error(MintingError::InvalidRecipient);
         }
     }
     ```
